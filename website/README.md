# Nexora website

Одностраничный статический сайт лаунчера Nexora. Только HTML, CSS, JavaScript и PowerShell: без сборщиков, backend и сторонних JS-пакетов.

## Что на странице

- Hero с реальным скриншотом главного экрана и ключевыми характеристиками.
- Блок возможностей: источники каталога, rqbit, HTTP с докачкой, SHA-256, библиотека, настройки.
- Галерея интерфейса: библиотека, карточка игры, настройки.
- Сценарий из трёх шагов и блок загрузки с версией, размером и датой файла из `releases.json`.
- FAQ и подвал со ссылкой на репозиторий GitHub.
- Переключение языка RU / EN / UA, выбор сохраняется в `localStorage`.
- Ссылки на GitHub Releases и исходный код появляются автоматически, когда сайт открыт с `*.github.io`, либо задаются через `<meta name="nexora-repo" content="owner/repo">`.

## Локальный запуск

Из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\website\Serve-Website.ps1
```

Открой `http://127.0.0.1:8080/`. Скрипт отдаёт `dist`, если он существует, иначе исходные файлы сайта. Установщики по пути `downloads/` берутся из `artifacts/installer`.

## Production-сборка

```powershell
powershell -ExecutionPolicy Bypass -File .\website\Build-Website.ps1
```

Скрипт:

1. Читает версию из `src/Nexora.App/Nexora.App.csproj` и сверяет её с `installer/Nexora.iss`.
2. Собирает `releases.json` из установщика текущей версии в `artifacts/installer`.
3. Копирует сайт в `website/dist` и кладёт туда текущий установщик.

Если установщик текущей версии отсутствует или версии расходятся, сборка завершается ошибкой. Загружай **содержимое** `website/dist` на статический хостинг.

## GitHub Pages

В репозитории есть workflow `.github/workflows/pages.yml`. Он публикует папку `website` как есть и подменяет ссылку установщика на страницу последнего GitHub Release, потому что бинарник не хранится в репозитории. Workflow запускается по пушу в `main`, вручную и после публикации нового релиза.

1. Создай релиз и приложи к нему `Nexora-Setup-<версия>-win-x64.exe`.
2. В GitHub открой **Settings → Pages** и выбери **Source: GitHub Actions**.
3. Запушь изменения в `main` или запусти workflow вручную.

Для локальной сборки с установщиком и для Pages используются разные источники загрузки: локально файл отдаётся из `dist/downloads`, на Pages кнопка ведёт на страницу релизов.

## Структура

```
website/
├── index.html              # разметка страницы
├── styles.css              # тёмная тема, сетки, адаптив
├── script.js               # языки, releases.json, ссылки на GitHub
├── releases.json           # манифест текущей сборки (генерируется)
├── assets/
│   ├── logo-mark.png       # белый знак для тёмного интерфейса
│   ├── logo.png            # исходный знак 200×200
│   └── screens/            # скриншоты лаунчера
├── Build-Website.ps1
└── Serve-Website.ps1
```

## Ограничения

- Сайт не выдумывает дату публикации: `releaseDate` в манифесте остаётся `null`, пока релиз не опубликован.
- Установщик не подписан цифровым сертификатом; сайт предупреждает об этом до скачивания.
- Автоматического канала обновлений лаунчера нет, поэтому сайт не обещает автообновление.
- Минимальные требования к CPU и памяти в проекте не заданы и на сайте не указаны.
