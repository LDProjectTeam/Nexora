# Vellum website

Независимый статический сайт лаунчера. Он использует только HTML, CSS, JavaScript и PowerShell для подготовки выпуска; backend и сторонние JavaScript-пакеты не нужны. Функции и сведения на страницах сверены с `src/Vellum.App`, `src/Vellum.Core`, `installer/Vellum.iss` и существующими файлами сборок.

## Локальный запуск

Из корня репозитория выполни:

```powershell
powershell -ExecutionPolicy Bypass -File .\website\Serve-Website.ps1
```

Открой `http://127.0.0.1:8080/`. Скрипт обслуживает исходные файлы сайта, а после production-сборки автоматически переключится на папку `dist`.

## Production-сборка

```powershell
powershell -ExecutionPolicy Bypass -File .\website\Build-Website.ps1
```

Скрипт сверяет версии в `.csproj` и установочном скрипте, создаёт `releases.json` из реально существующих установщиков и собирает отдельную папку `website/dist`. В неё попадает только текущий установщик Vellum; предыдущие сборки описаны в архиве сайта, но не копируются и не публикуются. Загрузи **содержимое** `website/dist` на любой статический веб-хостинг. При выкладке новой версии повтори сборку и замени прежнее содержимое сайта.

Сборка ссылается на локальный `artifacts/installer/Vellum-Setup-<версия>-win-x64.exe`. Если файла текущей версии нет или версии проекта и установщика не совпадают, сборка завершится ошибкой.

## GitHub Pages

Сайт опубликован по адресу https://ldprojectteam.github.io/Vellum/. Публикацией управляет workflow `.github/workflows/pages.yml`: он берёт файлы из `website`, подставляет в `releases.json` ссылку на установщик из последнего GitHub Release и выкладывает результат на Pages. Новый релиз с файлом `Vellum-Setup-<версия>-win-x64.exe` запускает публикацию автоматически.

## Источник данных и ограничения

- Версия берётся из `src/Vellum.App/Vellum.App.csproj` и сверяется с `installer/Vellum.iss`.
- Размер и отметка времени установщика берутся из файла сборки. Отметка времени не выдаётся за дату публикации.
- Предыдущие версии в `artifacts/installer` — инвентарь файлов рабочей копии. Источник не обозначает их опубликованными релизами и не содержит описаний изменений.
- Системные требования ограничены сведениями из target framework, RID и Inno Setup. CPU и память в проекте не заданы.
- Не найден публичный канал поддержки, API актуальных версий, авторизация, сервер релизов или API сайта. Сайт не имитирует их наличие.
- Интерфейс использует системный шрифт Windows и не загружает сторонние webfonts или JavaScript-библиотеки.

## Вариант интеграции будущих релизов

Оставить сайт и метаданные статическими: CI выпускает установщик и одну публичную JSON-запись с версией, датой релиза, ссылкой на файл, размером и SHA-256; тем же шагом собираются release notes из подтверждённого журнала изменений. Сайт читает опубликованный JSON и показывает только выпущенные сборки. Если в будущем понадобится обновление самого приложения, клиентский updater следует реализовать отдельно: он читает тот же manifest по HTTPS, проверяет хеш и подпись перед применением загрузки. Секреты CI не попадают в сайт. Сейчас эта интеграция не реализована, поскольку у проекта нет сервера релизов и updater самого лаунчера.

Текущий установщик в проекте не подписан цифровым сертификатом; сайт показывает это предупреждение перед скачиванием.
