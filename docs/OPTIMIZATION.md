# Оптимизация хранения данных и производительности Nexora

Документ фиксирует результаты аудита хранилища лаунчера, внедрённые изменения и
оставшиеся точки роста. Замеры сделаны на реальном профиле
`%APPDATA%\Nexora` (259 файлов кэша обложек, 35.98 МБ) в ноябре 2026.

---

## 1. Что уже оптимизировано

### 1.1. Обложки, баннеры и скриншоты → WebP

Раньше `SteamArtworkService` сохранял ответ CDN как есть: `library_hero.jpg`
мог быть 3840×1240 и весить 1–3 МБ, хотя в интерфейсе он показывается шириной
1280 px. Теперь каждая картинка проходит через `ArtworkImageOptimizer`:

| Тип | Макс. ширина | Качество | Куда попадает |
|---|---|---|---|
| Cover (карточка) | 640 px | 82 | `%APPDATA%\Nexora\artwork\*.webp` |
| Banner / hero | 1600 px | 78 | `%APPDATA%\Nexora\artwork\*.webp` |

- уменьшение только вниз (маленькие обложки не растягиваются);
- EXIF-ориентация применяется, метаданные (EXIF/XMP/ICC) удаляются;
- если WebP получается больше исходного компактного JPEG, остаётся исходник;
- запись идёт через временный файл + `File.Move`, поэтому обрыв не оставляет
  битых картинок;
- параллельных конвертаций не больше двух (пик памяти на 4K-баннер ~20 МБ).

**Результат на реальном кэше:**

| Показатель | До | После |
|---|---:|---:|
| Размер кэша | 35.98 МБ | **6.03 МБ** |
| Файлов | 259 | 233 |
| Формат | 166 JPEG + JSON | **140 WebP** + JSON |
| `library_hero_v1` | ~1–3 МБ, 3840×1240 | **128–168 КБ, 1600×517** |

Экономия ~83 %. Первичная конвертация 165 картинок заняла ~10 с в фоне,
повторный запуск обслуживания — 64 мс.

### 1.2. Обслуживание кэша artwork

`ArtworkCacheMaintenance` запускается в фоне при старте и:

- конвертирует старые JPEG/PNG в WebP и обновляет JSON-метаданные;
- удаляет картинки, на которые не ссылается ни одна запись (остатки старых
  версий имён `_v1`, `_v3`, `_v20`);
- удаляет недокачанные `.tmp`/`.download` и устаревшие `.miss` (7 дней);
- удаляет «висячие» метаданные (30 дней) и записи старше 150 дней;
- держит общий размер кэша ≤ 200 МБ (вытесняет самые старые записи).

Оригиналы, сконвертированные в текущем запуске, удаляются только на следующем
старте: карточка, уже загрузившая старый путь в память, не «мигает» битой
картинкой.

### 1.3. Память под обложки в UI

`StringToImageSourceConverter`:

- декодирует WebP через SkiaSharp в `BitmapSource` нужной ширины (400 px для
  карточек, 1280 px для hero);
- кэш ограничен 96 МБ / 180 изображениями с LRU-вытеснением (раньше
  `ConcurrentDictionary` рос без предела, пока пользователь листает каталог);
- ключ кэша включает `LastWriteTime`, поэтому обновлённая обложка не остаётся
  старой;
- локальные файлы читаются с `BitmapCacheOption.OnLoad` — файл больше не
  удерживается открытым, и обслуживание кэша может его переписать/удалить.

### 1.4. `library.json`

- сохранение пропускается, если сериализованный JSON не изменился (прогресс
  загрузки пишется раз в 5 с, но реальная запись теперь только при изменении);
- запись атомарная: `library.json.tmp` → `File.Replace` с одной резервной
  копией `.bak`. Раньше файл перезаписывался на месте, и падение процесса
  могло оставить обрезанный JSON;
- убран лишний `ReadAllText` предыдущей версии на каждое сохранение.

### 1.5. Логи и настройки

- Debug-логи и консольный логгер включаются только под отладчиком или при
  перенаправленном stdout (запуск через `Run-Launcher.ps1`). Обычный запуск
  оконного приложения больше не форматирует debug-сообщения в пустоту.
- «Очистить кэш» в настройках теперь учитывает и очищает `artwork` и
  `steam-metadata`; размер кэша в настройках показывает все четыре папки,
  а не только `staging` и `torrents`.

### 1.6. Мусор в репозитории

Добавлен `tools/Clean-DevArtifacts.ps1` (по умолчанию только отчёт):

```powershell
powershell -ExecutionPolicy Bypass -File tools\Clean-DevArtifacts.ps1
powershell -ExecutionPolicy Bypass -File tools\Clean-DevArtifacts.ps1 -Apply
```

Скрипт оставляет 3 последних установщика, 2 последних `publish-portable*`,
1 бэкап профиля и удаляет `bin/obj`, `artwork-debug*`, `stdout.txt`/`stderr.txt`.
Текущая оценка — **14.6 ГБ** освобождаемого места (из 19.35 ГБ репозитория).

## 2. Где какие данные лежат

| Путь | Что | Размер | Политика |
|---|---|---:|---|
| `%APPDATA%\Nexora\artwork` | обложки/баннеры WebP + JSON-метаданные | ≤ 200 МБ | WebP, cap + LRU по времени, 150 дней |
| `%APPDATA%\Nexora\library.json` | установленные игры и прогресс | ~4 КБ на 2 игры | атомарно, `.bak`, пропуск идентичных |
| `%APPDATA%\Nexora\settings.json` | настройки | < 1 КБ | пишется при изменении |
| `%APPDATA%\Nexora\torrents` | fast-resume торрентов | ~50 КБ | очищается кнопкой |
| `%APPDATA%\Nexora\steam-metadata` | карточки Steam Store | 9–27 КБ/игра | TTL 14 дней (позитив) / 7 дней (негатив) |
| `<папка лаунчера>\Library` | сами игры | гигабайты | пользовательские данные |
| `artifacts\installer`, `publish-portable*`, `bin/obj` | артефакты сборки | 14.6 ГБ | скрипт очистки |

`data/games.json` (встроенный каталог) сейчас пуст; каталог формируется
источником Rutor/Steam. Файл оставлен для пользовательских каталогов и
дополнительных URL из настроек.

## 3. Что ещё стоит оптимизировать

Приоритеты: **P1** — заметно влияет на пользователя, **P2** — средний эффект,
**P3** — косметика/на будущее.

| # | Область | Проблема | Предложение | Приоритет |
|---|---|---|---|---|
| 1 | `SteamFeaturedGamesService` | До 10 последовательных поисков Rutor по 10 с; при медленной сети главная «В тренде» грузится десятки секунд | Параллелить с `SemaphoreSlim(3)` и кэшировать готовый список на 5–10 минут на диск | P1 |
| 2 | `steam-metadata` | Кэш не чистится: просроченные JSON остаются навсегда | Удалять файлы старше 30–60 дней при записи; хранить только нужные поля, обрезать HTML-описание | P2 |
| 3 | Каталог на главной | `ItemsControl` не виртуализирован; при тысячах карточек создаётся всё дерево | Включить `VirtualizingStackPanel`/`VirtualizingWrapPanel`, когда каталог вырастет | P2 |
| 4 | Матчинг названий | `RutorGameSource`/`ArtworkTitleMatcher` создают `Regex` на каждый вызов (static-вызовы с внутренним кэшем на 15 шаблонов) | Вынести горячие шаблоны в `static readonly Regex(..., Compiled)` | P3 |
| 5 | Настройки | Каждое изменение слайдера/чекбокса вызывает `SaveAsync` | Debounce 300–500 мс | P3 |
| 6 | Диагностика | Файловых логов нет (только консоль при запуске из скрипта) | Опциональный rolling-лог 2×5 МБ, выключен по умолчанию | P3 |
| 7 | Размер поставки | `libSkiaSharp.dll` +9 МБ | Приемлемо; при жёстком лимите — WIC + libwebp | P3 |
| 8 | `tools/torrent-engine` | 2.3 ГБ `target/` от Rust-сборки | `cargo clean` перед архивацией; не чистится скриптом автоматически | P2 |
| 9 | Скриншоты в каталоге | `screenshots` пока не кэшируются на диск | Если появятся в UI — переиспользовать тот же WebP-конвейер | P3 |

## 4. Изменённые файлы

- `src/Nexora.Core/Helpers/ArtworkImageOptimizer.cs` — новый: WebP + downscale.
- `src/Nexora.Core/Services/ArtworkCacheMaintenance.cs` — новый: миграция и чистка кэша.
- `src/Nexora.Core/Services/SteamArtworkService.cs` — сохранение artwork в WebP, ленивая миграция старых JPEG.
- `src/Nexora.Core/Helpers/PathHelper.cs` — пути `artwork`/`steam-metadata`.
- `src/Nexora.Core/Services/GameManager.cs` — атомарное и экономное сохранение `library.json`.
- `src/Nexora.App/Converters/ValueConverters.cs` — WebP-декодер, LRU-кэш, `OnLoad`.
- `src/Nexora.App/Views/HomeView.xaml.cs` — определение готовности WebP-обложки для hero-перехода.
- `src/Nexora.App/ViewModels/SettingsViewModel.cs` — учёт и очистка artwork/steam-metadata.
- `src/Nexora.App/App.xaml.cs` — фоновое обслуживание кэша, уровень логов.
- `src/Nexora.Core/Nexora.Core.csproj` — SkiaSharp 2.88.9 (MIT).
- `tests/Nexora.Tests/ArtworkStorageTests.cs` — новые тесты конвертации и обслуживания кэша.
- `tools/Clean-DevArtifacts.ps1` — очистка артефактов сборки.

> Почему SkiaSharp, а не ImageSharp: начиная с 3.2.0 ImageSharp требует
> лицензионный ключ на этапе **Release-сборки** (`error: No Six Labors license
> found`). SkiaSharp распространяется по MIT и включает WebP-кодек, поэтому
> выбран он.

## 5. Проверка

```powershell
# тесты
.\.dotnet\dotnet.exe test tests\Nexora.Tests\Nexora.Tests.csproj -c Debug

# сборка приложения
.\.dotnet\dotnet.exe build src\Nexora.App\Nexora.App.csproj -c Debug

# состояние кэша artwork
Get-ChildItem "$env:APPDATA\Nexora\artwork" -File |
    Group-Object Extension |
    ForEach-Object { "{0}: {1}" -f $_.Name, $_.Count }
```

Ожидаемо: `106/106` тестов, в кэше только `.webp` + `.json`, суммарно
несколько мегабайт вместо десятков.
